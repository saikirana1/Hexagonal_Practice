2. Domain layer

Keep the domain independent of FastAPI, SQLModel, and PostgreSQL.

Use TypedDict or another lightweight functional data representation instead of domain classes.

Create:

Todo:
- id: UUID
- title: str
- description: str | None
- completed: bool

Create pure functions such as:

create_todo(title, description)
update_todo(todo, title, description, completed)

These functions should not perform database operations or mutate existing data.

For update_todo(), return a new Todo rather than modifying the existing Todo.




4. Application layer

Create functional use cases:

create_todo_use_case()
get_todos_use_case()
get_todo_use_case()
update_todo_use_case()
delete_todo_use_case()

Inject repository functions into the use cases as function arguments.

Example concept:

def create_todo_use_case(
    save_todo,
    title,
    description,
):
    todo = create_todo(title, description)
    return save_todo(todo)

The use-case layer must NOT import SQLModel, FastAPI, or PostgreSQL.


5. PostgreSQL adapter

Use SQLModel only inside the PostgreSQL adapter.

Create a SQLModel table model:

TodoModel:
- id UUID primary key
- title
- description
- completed

Implement repository functions:

create_todo_repository()
get_all_todos_repository()
get_todo_repository()
update_todo_repository()
delete_todo_repository()

These functions should accept a SQLModel Session where required.

Create conversion functions:

to_domain(model)
to_model(todo)

The domain Todo must remain independent of SQLModel.

7. FastAPI adapter

Create REST endpoints:

POST   /todos
GET    /todos
GET    /todos/{todo_id}
PUT    /todos/{todo_id}
DELETE /todos/{todo_id}

Use Pydantic request models for HTTP input.

The FastAPI router should be an inbound adapter.

It should:
- receive HTTP requests
- validate input
- inject repository functions
- call the functional use case
- convert the result to an HTTP response
- handle appropriate errors

Do not put business logic inside the router.


8. Dependency injection

Use FastAPI Depends() only at the infrastructure/adapter boundary.

For example, create repository functions using the current database session:

save_todo = lambda todo: create_todo_repository(session, todo)

Then pass that function into the use case.

Keep the use case unaware of FastAPI and SQLModel.


9. Functional programming requirements

Follow these rules:

- Prefer functions over classes.
- Avoid mutable global state.
- Avoid domain classes.
- Avoid service classes.
- Avoid repository classes.
- Keep domain functions pure.
- Do not mutate domain objects.
- Return new data structures when changing state.
- Inject side effects as functions.
- Keep database operations at the adapter boundary.
- Keep HTTP operations at the adapter boundary.
- Use type hints everywhere.
- Use small composable functions.
